**核心设计取舍**：

- **收成单文件 SPA**。多文件版（`index.html` + `product/p01…p30.html`）在本地 `file://` 下跨文件跳转失效，用户实测「点商品卡变成一大串代码」。单文件 + hash 路由彻底解决「卡墙 → 详情 → 返回卡墙」全链路。
- **数据在采集阶段就固化成 JSON**，网页生成阶段只做「读 JSON → 渲染」，不联网。所以页面可离线、可复现、可 diff。
- **一商品一独立标签页**。飞瓜同一个标签页里连续取多个商品，接口会在第 5~9 个之后开始「假返空」（HTTP 200 但 `Data: null`），必须开新标签页取完即关。

## 3. 数据源总览

### 3.1 飞瓜数据（抖音版）· 接口清单

飞瓜的接口分两类，这是整套方案能不能自动化的分水岭：

| 接口路径 | 用途 | 是否加密 | 需要 ts/sign |
|---|---|---|---|
| `goodDetails/mainpart`、`otherPart`、`overview/stat` | **商品详情主体** | 🔒 `Encrypt:true` | 是 | 
| `portrait/goodsTransactPortray` | 受众画像 | ✅ 明文 | 否（只认 gid） |
| `GetGoodsCommentPolarityStat` | 评价极性统计（好评/中评/差评计数） | ✅ 明文 | 否 |
| `GetGoodsCommentWord` | 16 类分类评价词云 | ✅ 明文 | 否 |
| `GetGoodsCommentList` | 商品评价列表（**含真商品主图**） | 🔒 `Encrypt:true` | 否 |
| `getSegmentCommentsV2` | 关键词维度评价原文 | ✅ 明文 | 否 |
| `aweme/loadAwemeAnalysis`、`aweme/search/items` | 带货视频列表 | ✅ 明文 | 否 |
| `aweme/GetAwemeMarketingKeyWordList` | 视频内容词云 | ✅ 明文 | 否 |
| `blogger/list`、`blogger/concentration`、`blogger/blogger/type/analysis` | 带货达人 / 集中度 / 达人类型结构 | ✅ 明文 | 否 |

**关键结论**：
- 商品详情主接口加密 → **卡片层只能读渲染好的 DOM**（脚本 03 的做法）。
- 其余几组（视频/达人/词云/画像/评价）明文且只认 gid → 可以在页面里直接 fetch 重放，**不需要 ts/sign**，这是能批量化自动化的基础。
- 但「明文」≠「裸 fetch 能拿到」——`GetGoodsCommentList` 虽是明文返回体，裸 `fetch` 拿到的仍是密文：**解密发生在页面自己的 fetch 包装里**。详见第 7 章坑 8。

### 4.5 派生字段：计算口径

这些字段**飞瓜不直接给**，是本模块算出来的，口径必须写清：

| 派生字段 | 计算口径 | 边界 |
|---|---|---|
| `price_est` 推算价格 | **佣金金额 ÷ 佣金率**（如 ￥2.6 ÷ 5% = ¥52） | 无佣金标注 → 显示「无佣金标注，无法反推」；**不是官方定价** |
| `rate_bad` 差评率 | 差评计数 ÷ 全部评价计数 × 100 | 无评价数据 → 留空显示 `—`（30 个中 28 个有） |
| `rate_good` / `rate_mid` | 同上（好评 / 中评） | 同上 |
| `mainAudience` 主要消费人群 | 性别取「女性」占比 + 年龄取 Top2 + 地域取前 3，拼成一句话 | 无画像 → 「该链接受众画像数据不足」 |
| `sellingPoint` 一句话卖点 | 标题去噪（去 `【】`、品牌名、官方/正品/包邮/同款/明星/达人专属等促销词、`（）` 内容、英文数字）后，保留 **形态＋功效** 描述，截 26 字；为空则回退标题前 20 字 | 见 5.4 |
| `gram` 每克/每单位均价 | 价格 ÷ 规格数字（从规格词云 + 属性原文正则 `(\d+)(g|克|ml|毫升|片|支)`） | 缺规格或缺价格 → 「无法计算」 |
| `pos` 货架定位 | ≤¥60 → 引流款（低价高佣金）；≥¥150 → 利润款（中高价位）；其余 → 主推款/复购款 | 经验阈值，非平台口径 |
| `sku_type` SKU 形态 | 标题含 拍一发/套装/2件/两件/组合/礼盒/×2 → 套装多件装，否则单品 | — |
| `form` 内料形态 | 标题含「眼油」→ 纯油（眼部精华油）；含 膜/贴 → 膜贴类；含「霜」→ 霜膏类；否则 精华液类 | 仅按标题判定 |
| `tier` 达人层级 | 1万–50万粉 → 中腰部；>50万 → 腰部以上；<1万 → 尾部 | — |

### 5.2 公共基座 `pcommon.py`

所有脚本共用，是整套链路的「通道层」。核心能力：

| 函数 | 作用 |
|---|---|
| `wb(action, args)` | 调用 Kimi WebBridge（`127.0.0.1:10086`）。**坑：必须用 `curl.exe` + `--data-binary @文件` 传中文 payload** |
| `ev(code)` | 在浏览器里执行 JS 并取回结果（`Runtime.evaluate`） |
| `click_tab_full(label)` | 点飞瓜的 tab（先清遮罩，再派发完整 PointerEvent 序列） |
| `install_hook()` / `cap()` / `cap_json(kw)` | 注入 fetch/XHR 拦截器，捕获接口原始响应体 |
| `scroll_all(times)` | 滚动触发懒加载 |
| `check_login()` | 探活飞瓜登录态（cookie `FEIGUADY2`） |
| `tier_mid(tier)` | 把档位（`100w+`）换算成中位数，用于排序 |
| `norm_title()` / `jaccard(a,b)` | 标题归一化 + 相似度，用于同品去重 |
| `_dcode(n)` | 生成飞瓜要求的日期码（`fromDateCode` / `toDateCode`） |

**进程内强制清代理**（`HTTP_PROXY` 等 6 个环境变量），否则 WebBridge 通道会走代理导致连不上。

### 5.3 逐脚本逻辑

**① `02_collect_pool.py` — 扩池与定稿**
1. 打开「商品销售榜」，类目筛「个护家清」、周期「月榜」；
2. 对 8 个关键词逐个搜索，滚动加载，从「查看详情」链接正则抽 `gid`/`ts`/`sign` + 榜单列数值；
3. 累加写入 `pool_raw.json`（不覆盖，支持多类目追加）；
4. **眼部校验**：标题必须命中眼部相关词，否则剔除；
5. **同品归一化去重**：标题去噪后算 Jaccard 相似度，**≥0.72 判为同品**，保留销售额档更高的一条；
6. **排序**：销售额档中位数 → 销量档中位数 → 浏览量，降序；
7. 取前 30 → `top30.json`。

> 实测：池子 41 条 → 解析成功 41 → 眼部校验通过 41（本类目关键词已是眼部）→ 去重后 **37** 条 → 取 **TOP30**。

### 5.4 关键算法

**(a) 爆款视频拆解算法**（核心差异化）

筛选：
```
排除 粉丝 > 100 万              → 标注「粉丝>100万（大V，不可复制）」
排除 账号类型含 旗舰店/品牌/自营/官方 → 标注「品牌自营账号（品牌广告）」
排除 标题含 9.9/免单/抽奖/免费送   → 标注「福利款」
中腰部（1万–50万粉）优先，被排除的仍列出并打标
```
实测：216 条进入拆解，75 条被排除（仍在页面上列出并说明原因），7 个链接本月无带货视频 → 如实标注。

每条视频产出的 7 列：

| 列 | 算法 |
|---|---|
| **时间** | `PublishTime` 原值 |
| **开头（黄金3秒）** | `hook_type()` 按优先级匹配关键词 → 活动/促销开头、提问式、明星/信任背书、人设/年龄共鸣、痛点直击、场景代入、种草直给 |
| **视频链接** | 抖音原视频直链 + 达人主页，可点回复核 |
| **打什么痛点** | 标题文案命中 `PAIN` 词表（眼袋/黑眼圈/细纹/干纹/泪沟/松弛…） |
| **框架类型** | `frame_type()` 优先级：AI → 明星 → 活动 → 剧情 → 人设 → 达人 → 痛点 → 场景 → 种草（取值对齐《爆款拆解框架》表） |
| **框架拆解** | `frame_seq()` 生成段落序列：开头 → 痛点放大 → 利益点输出 → 信任背书 → 活动逼单 → （时长≥60s 再加）重复强化+二次逼单 |
| **分析** | `analysis_of()` 生成三句：**亮点**（3 秒留人用什么）／**转化点**（利益点+活动锚点+逼单话术）／**爆点**（信任背书+时长+达人层级可复制性） |

另有 **0-3s / 3-10s / 10-15s / 15s+** 四段式 + 标题文案原文（拆解依据）。

> **必须如实说明的缺口**：未做 ASR 逐句口播转写。拆解依据是「视频标题文案 + 实测时长 + 达人粉丝层级 + 该商品评价/内容词云的功效·成分·痛点词库映射」，**不是逐帧听写**。页面上每一处都标了这一点。

**(b) 一句话卖点提炼 `one_line_sp()`**
```
标题 → 去掉【】内容 → 去掉官方/正品/旗舰/包邮/同款/明星/推荐/达人专属/升级/版/款等词
     → 去掉（）内容 → 去掉英文数字 → 去掉品牌名（按 / ／ | ｜ 、 拆）
     → 截 26 字 → 若为空则取标题前 20 字
```

**(c) 主要消费人群**
`受众画像 → Gender` 取「女性」占比 + `Age` 按占比降序取 Top2 + `Region/Province` 取前 3 → 拼成一句话；无画像则如实写「该链接受众画像数据不足」。

**(d) 兜底语料逻辑（数据贫瘠链接专用）**
部分链接评价数为 0~3 条，评价词云全空。此时：
```
corpus = 该链接所有带货视频文案 + 内容词云 + 属性 tab 原文
按品类词表（功效/成分/气味/质地/技术/规格/场景/受众/外观/痛点）在 corpus 里检索命中的词
→ 若评价词云空但兜底命中，页面在 `coreFrom` 里标注来源为「视频文案/内容词云兜底」
→ 若两者都没有，如实写「无（该链接评价与视频均未出现）」
```
**不编数据**是硬约束。

### 5.5 真·商品主图抓取（最有技术含量的一环）

**问题**：飞瓜商品详情页的 `img.img-product` **从头到尾都是 1491B 的 base64 占位图**。高频轮询 90 秒、抢在 `onerror` 替换前读，都拿不到真 URL。

**走不通的路（都已排除，别再试）**：
1. DOM 直读 —— 恒为占位图；
2. 抖店 `haohuo.jinritemai.com` —— 浏览器导航被主机安全策略拦；curl 页面纯 JS 渲染（11.9KB 无图）；`promotion/pack` 接口有反爬（200 但 0 字节）；
3. 裸 `fetch('/api/v3/goods/GetGoodsCommentList')` —— 拿到的是**密文**（`Data:"Gk8cOiVdrgYlI1tR..."`）；
4. Vue 组件树 / localStorage / sessionStorage 深挖 —— 0 命中。

**通的解法**：真图在**加密接口** `GetGoodsCommentList` 的响应里，字段是 `Data.Items[0].GoodsInfo.CoverUrl`。页面解密后必然调用 `JSON.parse`，所以：

```js
// tmp/_jp_hook.js —— 钩住 JSON.parse，在「解密之后、渲染之前」截明文
var orig = JSON.parse;
JSON.parse = function(t){
  if (typeof t === 'string' && /ecombdimg|ecom-shop-material/.test(t)) {
    window.__jp.push(t.slice(idx - 500, idx + 2200));   // 留存上下文
  }
  return orig.apply(this, arguments);
};
```

抓取顺序：
```
开详情页(newTab) → 注 _helper.js（清遮罩）
→ 注 _jp_hook.js
→ click_tab_full('商品评价')       ← 必须点这个 tab，才会触发该接口
→ 等 11 秒
→ 读 window.__jp → 正则抠 "CoverUrl":"(https?://...)"
→ curl 带 -e https://dy.feigua.cn/ 下载 → .part → os.replace
→ close_tab
```

实测结果：**28/30 拿到 800×800 真商品主图**（单张 40KB~570KB）。剩 2 个链接本身无评价数据 → 接口不返回该字段 → **如实留空，不塞占位图**。

> **这个方法对所有加密接口通用**：只要页面自己会解密，钩 `JSON.parse` 就能拿到明文，不用去逆向加密算法。

## 7. 工程坑位（复用这条链路必看）

| # | 坑 | 现象 | 解法 |
|---|---|---|---|
| 1 | **隐形 loading 遮罩** | 飞瓜有 `.el-loading-mask`，`elementFromPoint` 永远命中它 → 点击**静默失效** | 先 `querySelectorAll('.el-loading-mask,.v-modal').forEach(e=>e.remove())`，再对目标元素派发**完整 PointerEvent 序列**（`tmp/_helper.js` 已封装） |
| 2 | **接口「假返空」** | 同一标签页连续取多个商品，第 5~9 个之后 `Data` 全为 `null`（HTTP 仍 200） | **一商品一独立标签页**：`navigate newTab:true` → 取完 `close_tab` |
| 2b | **上下文未建** | `GetGoodsCommentWord` 直接调返回 `Code:500 接口不存在或不被支持`（看着像接口没了） | 必须**先点开「商品评价」tab** 再调接口 |
| 3 | **SPA 陷阱** | `navigate` 到只改 hash/query 的 URL 不会重新渲染 | 用 `newTab:true`，或先落别的路由再 `location.hash=...` |
| 4 | **商品图不能从 DOM 拿** | `img.img-product` 恒为 1491B base64 占位图 | 走第 5.5 节的 `JSON.parse` 钩子方案 |
| 5 | **脚本里禁用 `os.remove()`** | 触发「批量删除确认」，整条链路被中断 | 用「先下 `.part` → 成功再 `os.replace`」 |
| 6 | **跨文件跳转在 `file://` 下不可靠** | 用户实测「点商品卡变成一大串代码」 | 收成单文件 + hash 路由，**不要拆回多文件** |
| 7 | **`screenshot` 指定 selector 报错** | `element has no layout box`；多标签页时区域截图可能截到别的标签页 | 用 `evaluate` 验证 DOM，别靠看图 |
| 8 | **★ 接口返回是密文，裸 `fetch()` 拿不到明文** | 拿到 `Data` 是一串 Base64 密文 | 钩 `JSON.parse`，在解密后、渲染前截明文（`tmp/_jp_hook.js`）。通用解法 |
| 9 | **抖店在本机走不通** | 导航被主机安全策略拦（`SENSITIVE_APPROVAL=TIMED_OUT`）；API 反爬 | **别再往这条路上花时间** |

**另两个运维坑**：
- **WebBridge 守护进程保活**：前台跑 `kimi-webbridge start` 会「假成功」（日志显示已 listen，命令一结束进程就被回收）。必须让父 shell 常驻，后台跑 `start; sleep 30000`。拉起后必须验 `running:true` **且** `extension_connected:true`。
- **飞瓜登录态会「假过期」**：长跑任务中途 `check_login()` 返回 `expired`，**不用重新登录** —— 直接 `navigate` 到 `https://dy.feigua.cn/` 刷新一下即回到 `normal`。
- **本地预览服务必须后台常驻**：`python -m http.server 8931 &` 在命令结束后会被回收，要用 `run_in_background` 单独起。
