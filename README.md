## 模块一 · 用户调研模块

**6 个产出**（顺序固定）：

1. 目标用户画像
2. 高频需求 TOP5（附频次）
3. 高频痛点 TOP5（附频次）
4. 我们必须解决的痛点（产品开发红线）
5. 用户话语词库
6. 用户决策权重排序

**版式**：上半「⚡ 结论速览 · 六大产出」（6 张卡）+ 下半「📂 数据明细」（6 栏目）+ 附 TOP10 品牌玩家。

**数据源**：飞瓜商品库（眼油品类 TOP10 玩家）+ 小红书笔记与评论。
**口径**：**所有品牌一视同仁**，不区分自家 / 竞品，语料来源按品牌正常标注。

**脚本链路**：`01b_collect_details` → `01_filter_comments` → `02_build_outputs` → `03_build_html` → `06_merge_xhs`

## 模块二 · 产品调研模块

**单文件 SPA**，hash 路由：

| 路由 | 页面 |
|---|---|
| `#/` | 商品卡墙（30 个商品链接，支持搜索 / 10 种排序 / 类目筛选） |
| `#/p/N` | 单品调研详情页（11 个板块） |
| `#/cmp` | 全品对标表（30 × 18 列） |
| `#/method` | 口径与方法 |

**单品详情页 11 个板块**（顺序固定，均为可折叠块，默认收起）：

速览 → 🧪 产品核心要素 → 🛒 货架策略 → 🎨 视觉/包装 → 📋 产品档案（21 行字段表） →
👥 消费人群 → 🗣️ 商品评价 → 🔥 爆款视频拆解 TOP10（逐条折叠）→ 👤 带货达人 → 💬 内容词云 → 🔗 数据来源

**卡面必显字段**：💡 一句话卖点 / 👥 主要消费人群 / 差评率

> 为什么要收成单文件：多文件版（`index.html` + `product/pNN.html`）在本地 `file://` 协议下跨文件跳转失效。
> 单文件 hash 路由彻底解决「卡墙 → 详情 → 返回卡墙」全链路。

**口径**：飞瓜商品销售榜（类目「个护家清」→ 月榜），关键词 眼油/眼部精华/眼精华/眼霜/眼膜/眼贴/眼周/眼部护理，
候选 41 条 → 眼部校验 → 同品去重 → **TOP30**，每个链接再单独挖视频 / 达人 / 词云 / 受众画像 / 评价极性。

完整口径、脚本清单与 9 个必知坑位见 `产品调研模块/README.md`；自检见 `产品调研模块/_check/selfcheck.md`。

### 三条铁律

1. **所有品牌一视同仁** —— 白云山不做对标基准、不单独高亮，与其他品牌完全同等呈现；
2. **版式固定** —— 入口商品卡墙 → 点开才是该链接的详情页 → 返回必须回到卡墙；
3. **拿不到的数据如实标注缺口，不编数据** —— 爆款拆解只做 TOP10，精不求多，且必须拆视频内容。

## 数据说明

`raw/` 与 `data/` 下均为从飞瓜、小红书、飞书抓取的原始 / 中间数据，属作业过程留档，**按需求一并上传**。

本地采集依赖真实浏览器登录态（Kimi WebBridge + 飞瓜登录），脚本可直接复用；**凭据不落在代码里**，
采集时从浏览器实时读取，因此仓库中不含任何 cookie / token。
