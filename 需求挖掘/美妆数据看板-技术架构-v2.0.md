# 美妆数据看板 · 技术架构 v2.0

> 版本 v2.0 · 2026-09-26
> 配套 PRD v1.0。核心转变：从「单文件空壳 + AI 手工填数据」转向「模块化真实数据流平台」。

---

## 一、设计原则

1. **胶水编程超集**：优先复用成熟方案（kimi-webbridge 驱动浏览器、罗盘/蝉妈妈页面上下文 fetch、本地 JSON 存储），自研代码只做连接、编排、适配业务逻辑。不重复造轮子。
2. **代码驱动数据流**：采集 → 口径计算 → 视图模型 → 前端渲染，全程代码完成。禁止 AI 本地跑完手工把数据填进工作台。
3. **模块化分层**：每层单一职责，跨层只通过定义好的数据契约（JSON 文件 / 函数签名）通信。
4. **数据真实**：业务需要的数据必须技术得到 + 口径计算，拿不到就标「待积累/待接入」，禁止编造。
5. **前端样式不变**：沿用现有 Stripe 白色风格与原型外壳。

## 二、分层架构

```
┌─────────────────────────────────────────────────────┐
│  展示层 web/      单文件工作台，读视图模型 JSON 渲染，筛选联动 │
├─────────────────────────────────────────────────────┤
│  视图层 data-mart/  把计算结果组装成前端直接可用的视图模型     │
├─────────────────────────────────────────────────────┤
│  口径层 pipeline/   增速/占比/CR4·CR10/成分提取/热度分/玩家结构 │
├─────────────────────────────────────────────────────┤
│  采集层 collector/  驱动浏览器抓罗盘/蝉妈妈，落原始数据        │
├─────────────────────────────────────────────────────┤
│  存储层 data/       原始快照 + 计算结果（JSON 文件，按日期分区）│
└─────────────────────────────────────────────────────┘
```

**关键：筛选联动在前端对「视图模型」做计算**。视图模型包含全量明细数据，前端筛选（市场/类目/周期/多选）时对视图模型即时过滤+重算，不需要每次回后端。

## 四、数据流（代码驱动，非手工）

```
run.py 一键编排：
  1. collector 抓原始数据 → data/raw/<日期>/compass_product.json 等
  2. pipeline 读 raw → 算增速/占比/CR4/成分 → data/computed/<日期>/
  3. data-mart 读 computed → 组装视图模型 → web/data/view.json
  4. web/index.html 读 view.json → 渲染 + 筛选联动
```

**每个环节都是代码**。`python3 run.py` 一条命令跑完全链路，产出前端可直接打开的视图模型。

## 五、各层关键技术点

### 5.1 采集层 collector

- **浏览器单例串行**：kimi-webbridge 驱动真实 Chrome（带登录态），不并行。
- **罗盘必须在页面上下文 fetch**（msToken/a_bogus 每次变，外部拼 URL 会被风控）。
- **商品榜翻页拉满**：page_size 服务端固定 10，total=200，循环翻 20 页，按 product_info.id 去重。
- **商品图与链接**：`product_info.image_url`（缩略图）+ `product_info.product_detail_h5_url`（真实链接）直接取。
- **蝉妈妈接口请求体加密**：不解密，从 DOM 读渲染后的表格数据。

### 5.2 口径层 pipeline

| 模块 | 计算 |
|---|---|
| growth.py | 类目级环比=直接取罗盘 `cell_info.<指标>.<指标>_index_values.index_values.out_period_ratio`；商品级增速=本期近7天 vs 7天前快照（首日标「待积累」） |
| ingredient.py | 成分提取：优先蝉妈妈成分字段；取不到则解析商品标题/详情页文案抽成分词。成分增速=7天前 vs 今天排名/关联商品数变化+新上榜标记。热度分=关联商品数+销量加权+上榜频次 |
| strategy.py | CR4/CR10=该类目商品榜前4/前10 GMV 占比；玩家结构=按 brand_type（知名/非知名）+国际知名维度分国际大牌/新锐/白牌；价格带分布=商品 price_bin 直方图；SKU矩阵=TOP玩家商品按价格带分引流/利润/复购款；GO/NOGO=规则引擎（阈值见 PRD） |
| caliber.py | 罗盘区间值（lower/upper+unit）→ 可读字符串；货币符号（国内¥/海外$）；占比小数→百分比 |

### 5.3 视图层 data-mart

`build_view.py` 把 computed 结果组装成**扁平、前端友好**的视图模型 JSON：
- 每个看板一个视图（growth/trend/ingredient/product/strategy）
- 视图含**全量明细**（商品行含 name/brand/image_url/detail_url/price_bin/growth/category_path/supply_ratio），前端筛选时即时过滤
- 类目树（全量 19 一级 + 个护家清完整树）+ 各节点 hasData 标记

### 5.4 展示层 web

- **筛选条组件 filter-bar.js**：市场（含「全部」）+ 罗盘式级联类目（hover 逐级展开，**多选**）+ 周期。任何变化触发 `onFilterChange`，重算当前看板。
- **每个看板一个 JS 模块**，订阅筛选状态，对视图模型过滤+渲染。
- **联动**：类目趋势「看商品榜」跳转时把当前类目写入全局筛选状态，商品榜读取并预选。
- **成分库点击成分**：弹层显示关联商品 + 所属类目层级 + 是否多类目。
- **商品行**：`<img src=image_url>` 缩略图 + `<a href=detail_url target=_blank>` 点击跳转。

## 六、策略台的 LLM 位

策略台的 CR4/CR10/价格带/SKU/玩家结构是**确定性计算**（规则引擎可实现）。GO/NOGO 综合结论分两层：
- **本版**：规则引擎输出确定性结论（CR4>60%→难进入 等阈值规则）+ 数据可视化。
- **增强位（预留）**：接 LLM API，把结构化数据（规模/增速/集中度/玩家结构/价格带/SKU）作为 prompt 输入，输出自然语言综合研判。接口预留 `strategy.py: llm_conclude(structured_data)`，默认走规则引擎。

## 七、失败与降级

| 情况 | 策略 |
|---|---|
| 扩展未连接 / 登录失效 | 采集暂停，工作台标「数据待更新」，不补假数据 |
| 接口报错 | 重试 3 次（退避），仍失败则记录并跳过该类目 |
| 首日无快照 | 商品级增速标「待积累」，类目级仍可取罗盘现成环比 |
| 海外未接入 | FastMoss 标「待实测」，市场切海外显示空态 |

## 八、反模式（红线）

- ❌ AI 手工把数据填进 HTML（必须代码生成视图模型）
- ❌ 筛选条只做样式不联动数据
- ❌ 商品级环比编造数字（首日必须标待积累）
- ❌ 外部拼罗盘 URL 硬调（msToken 会变，必须页面上下文 fetch）
- ❌ 试图解密蝉妈妈请求体（从 DOM 读）
- ❌ 单文件堆砌所有逻辑（必须分层分文件）
