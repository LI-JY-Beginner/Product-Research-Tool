打开 config/_template.yaml，按注释填：

  3. brands：这个类目的品牌名，命中会加分
  4. noiseWords：看到就丢掉的干扰词（比如别的品类的词）

# 小红书评论采集工具包

把一个类目的小红书**帖子正文 + 评论**扒下来，过一遍水军过滤，
产出「评论汇总文档」+「需求 TOP5 / 痛点红线 / 决策权重」。

洁面（洗面奶）类目已用本工具包完整跑通：**115 篇笔记 / 802 条原始评论 → 450 条有效语料**。

## 三、换一个类目要改什么

复制 `config/_template.yaml` → 改名 `config/面膜.yaml`，只改 6 处：

### ① project（2 行）
```yaml
project:
  name: 面膜
  catKey: mask
  outputDir: ./产出/面膜              # ★ 相对路径 → 落在 xhs-scraper/产出/面膜/
                                      #   也可以填绝对路径，如 D:/我的项目/面膜
  session: xhs-mask-research          # ★ 每个类目一个独立名字，别重名
```

### ② category.words —— 品类词（决定"这条评论算不算相关"）
```yaml
category:
  words:
    - 面膜
    - 敷面膜
    - 补水
```
> 这是**最关键的一项**。评论里出现任意一个词才保留。
> 填太少 → 大量真实评论被判"无关"丢掉；填太多 → 垃圾混进来。
> **建议先只填 keywords 跑一轮，看抓回来什么，再回来补这项。**

### ③ keywords —— 搜索关键词（决定"能搜到哪些笔记"）
```yaml
keywords:
  - [面膜, 综合]
  - [面膜避雷, 吐槽]
  - [面膜推荐, 求安利]
  - [面膜测评, 测评]
  - [补水面膜, 需求]
```
> 20 组左右为宜。类型标签填：`综合` / `求安利` / `吐槽` / `测评` / `需求` / `痛点`。
> **吐槽类和测评类的真实反馈密度最高**，优先多配。

### ④ buckets —— 统计口径
```yaml
buckets:
  needs:                                    # 需求桶：用户想要什么
    - [功效诉求（补水/保湿）, '补水|保湿|水润|不干|滋润']
    - [价格性价比, '平价|便宜|性价比|学生|划算']
  pains:                                    # 痛点桶：用户踩了什么坑
    - [过敏 / 刺痛 / 泛红, '过敏|泛红|刺痛|灼热|痒|红肿|烂脸']
    - [无效 / 智商税, '(?<!有)没效果|无效|智商税|后悔|踩雷|不值']
```
> 格式 `[桶名, '正则']`，`|` 表示"或"，一个桶建议 5–20 个词。
> 痛点桶**自动做否定识别**：「不紧绷」「不假滑」不会被算成痛点。

### ⑤ decisionMap —— 决策权重映射
```yaml
decisionMap:
  功效诉求（补水/保湿）: 功效
  价格性价比: 价格
```
> 把需求桶归并到用户实际决策时的评判维度。不填也能跑（会退回用需求桶本身）。

### ⑥ doc —— 文档标题
```yaml
doc:
  title: 面膜 · 小红书评论汇总
  path: 个护家清 / 面部护理 / 面膜
```

**改完双击 `开始采集.bat`，输入 `面膜` 回车即可。**

> 除非你确定，否则用 `run_all.py`。

## 五、依赖（只有 3 个）

| 依赖 | 用途 | 怎么装 |
|---|---|---|
| **Python 3.9+** | 跑脚本 | 去 python.org 装，装时勾「Add to PATH」。工具包会**自动探测**解释器，找不到才需要设环境变量 `XHS_PYTHON` |
| **pyyaml** | 读配置文件 | `python -m pip install --only-binary=:all: pyyaml`（`环境自检.bat` 会帮你装） |
| **Kimi WebBridge** | 控制浏览器抓页面 | 需单独安装（不是 pip 包）。工具包会**自动探测**常见位置，找不到就跳过看门狗并提示——纯本地步骤（清洗/过滤/统计/出文档）照常能跑 |

> **路径不用改代码。** Python 和 WebBridge 两个路径都支持自动探测 + 环境变量覆盖
> （`XHS_PYTHON` / `XHS_DAEMON`）。`outputDir` 用相对路径 `./产出/<类目>`，
> 相对工具包根目录解析，解压在哪就落在哪。

**WebBridge 的两个硬要求：**
1. 守护进程必须是**常驻**的。直接跑 `kimi-webbridge.exe start` 会"假成功"——
   日志显示已监听，命令一结束进程就被回收。`run_all.py` 内置看门狗解决了这个。
2. 浏览器（Edge）要打开，且 **Kimi 浏览器扩展已启用**。
   自检看 `extension_connected: true`。

## 七、已知限制（如实说明，不装作能拿到）

1. **小红书只渲染部分评论。** 页面声明 1000 条的笔记，实际通常只能读到几十到一百多条。
   洁面这轮 115 篇平均约 7 条/篇，最多的 24 条。这是平台限制，不是脚本问题。

2. **`xsec_token` 会过期。** 把已经抓过的笔记再打开一遍，几乎拿不到新评论
   （实测二刷 115 篇只多 13 条）。**想扩量要回去重跑第①步拿新笔记**，
   而不是反复重刷同一批旧链接。

3. **搜索结果链接是 `/search_result/<nid>`，不是 `/explore/<nid>`。**
   这个坑已经处理了，但如果你自己改正则要注意——漏了 `search_result` 会静默采到 0 条且不报错。

4. **结果里混着 `/user/profile/` 的作者主页链接**，已过滤。

5. **不采任何非公开内容**，不做推测性补全；取不到的字段留空。

## 八、R1–R12 过滤规则

| 规则 | 剔除什么 |
|---|---|
| R1 | 营销文本（淘口令 / 加微 / 优惠券 / 外链…） |
| R2 | 空内容，或超短且无信息 |
| R3 | 与本品类/品牌均无关（低相关）← **最主力的一条**，靠 `category.words` 判定 |
| R4 | 同文案出现在 ≥3 个不同笔记（模板复刷） |
| R5 | 同一 IP 属地占比过高（疑似水军聚集；无属地数据时不启用，避免误杀整篇） |
| R6 | 同笔记同一小时零赞评论 ≥8 条（集中爆发） |
| R7 | 营销号昵称特征 |
| R9 | 不可改良项打标（物流 / 价格 / 客服 —— 保留但统计时剔除） |
| R10 | 完全重复的语料（同内容只计一条） |
| R11 | 纯话题标签串，剥掉 `#标签` 后没有实质表述 |
| R12 | 作者置顶 / 购买引导（去某宝、戳我、主页有…） |

洁面这轮的实际分布：**输入 873 → 保留 450，过滤 423**
（R3 无关 346 / R2 超短 49 / R11 纯标签 16 / R12 营销 6 / R1 广告 5 / R10 重复 1）。

## 九、两条统计纪律（决定数据可不可信）

1. **痛点桶走否定识别。** 「不紧绷」「不假滑」「没长脂肪粒」不会被算成痛点。
   同时排除「担心 / 怕 / 会不会」这类假设语境——那是需求信号，不是已发生的痛点。

2. **一条语料只进一个桶**（第一个命中的）。否则同一条话被重复计数，频次会虚高。

## 十、出问题先看这

| 现象 | 原因 / 怎么办 |
|---|---|
| 采到 0 条链接 | ① 小红书没登录 → 浏览器扫码登录<br>② 正则漏了 `search_result`（已修，别自己改回去）<br>③ WebBridge 扩展没连 → 打开 Edge 确认扩展启用 |
| 脚本全静默、body 返回 0 字 | 守护进程死了。**用 `run_all.py` 跑**，它有看门狗 |
| 提示「代理/连接被拒」 | 系统代理劫持 127.0.0.1。`run_all.py` 已自动清代理，别单独跑单步脚本 |
| 候选很多但有效语料少 | `category.words` 填太窄 → 看着 `filtered_log.json` 里的 R3 被剔条目补词 |
| 深挖几乎没新增 | `xsec_token` 过期，正常。回第①步重搜新笔记 |
| 端口 10086 被占 | 历史上有杀毒软件（金山毒霸）抢过这个端口，卸载或改端口 |

## 三、换一个类目要改什么

复制 `config/_template.yaml` → 改名 `config/面膜.yaml`，只改 6 处：

### ① project（2 行）
```yaml
project:
  name: 面膜
  catKey: mask
  outputDir: ./产出/面膜              # ★ 相对路径 → 落在 xhs-scraper/产出/面膜/
                                      #   也可以填绝对路径，如 D:/我的项目/面膜
  session: xhs-mask-research          # ★ 每个类目一个独立名字，别重名
```

### ② category.words —— 品类词（决定"这条评论算不算相关"）
```yaml
category:
  words:
    - 面膜
    - 敷面膜
    - 补水
```
> 这是**最关键的一项**。评论里出现任意一个词才保留。
> 填太少 → 大量真实评论被判"无关"丢掉；填太多 → 垃圾混进来。
> **建议先只填 keywords 跑一轮，看抓回来什么，再回来补这项。**

### ③ keywords —— 搜索关键词（决定"能搜到哪些笔记"）
```yaml
keywords:
  - [面膜, 综合]
  - [面膜避雷, 吐槽]
  - [面膜推荐, 求安利]
  - [面膜测评, 测评]
  - [补水面膜, 需求]
```
> 20 组左右为宜。类型标签填：`综合` / `求安利` / `吐槽` / `测评` / `需求` / `痛点`。
> **吐槽类和测评类的真实反馈密度最高**，优先多配。

### ④ buckets —— 统计口径
```yaml
buckets:
  needs:                                    # 需求桶：用户想要什么
    - [功效诉求（补水/保湿）, '补水|保湿|水润|不干|滋润']
    - [价格性价比, '平价|便宜|性价比|学生|划算']
  pains:                                    # 痛点桶：用户踩了什么坑
    - [过敏 / 刺痛 / 泛红, '过敏|泛红|刺痛|灼热|痒|红肿|烂脸']
    - [无效 / 智商税, '(?<!有)没效果|无效|智商税|后悔|踩雷|不值']
```
> 格式 `[桶名, '正则']`，`|` 表示"或"，一个桶建议 5–20 个词。
> 痛点桶**自动做否定识别**：「不紧绷」「不假滑」不会被算成痛点。

### ⑤ decisionMap —— 决策权重映射
```yaml
decisionMap:
  功效诉求（补水/保湿）: 功效
  价格性价比: 价格
```
> 把需求桶归并到用户实际决策时的评判维度。不填也能跑（会退回用需求桶本身）。

### ⑥ doc —— 文档标题
```yaml
doc:
  title: 面膜 · 小红书评论汇总
  path: 个护家清 / 面部护理 / 面膜
```

**改完双击 `开始采集.bat`，输入 `面膜` 回车即可。**

## 七、已知限制（如实说明，不装作能拿到）

1. **小红书只渲染部分评论。** 页面声明 1000 条的笔记，实际通常只能读到几十到一百多条。
   洁面这轮 115 篇平均约 7 条/篇，最多的 24 条。这是平台限制，不是脚本问题。

2. **`xsec_token` 会过期。** 把已经抓过的笔记再打开一遍，几乎拿不到新评论
   （实测二刷 115 篇只多 13 条）。**想扩量要回去重跑第①步拿新笔记**，
   而不是反复重刷同一批旧链接。

3. **搜索结果链接是 `/search_result/<nid>`，不是 `/explore/<nid>`。**
   这个坑已经处理了，但如果你自己改正则要注意——漏了 `search_result` 会静默采到 0 条且不报错。

4. **结果里混着 `/user/profile/` 的作者主页链接**，已过滤。

5. **不采任何非公开内容**，不做推测性补全；取不到的字段留空。

## 八、R1–R12 过滤规则

| 规则 | 剔除什么 |
|---|---|
| R1 | 营销文本（淘口令 / 加微 / 优惠券 / 外链…） |
| R2 | 空内容，或超短且无信息 |
| R3 | 与本品类/品牌均无关（低相关）← **最主力的一条**，靠 `category.words` 判定 |
| R4 | 同文案出现在 ≥3 个不同笔记（模板复刷） |
| R5 | 同一 IP 属地占比过高（疑似水军聚集；无属地数据时不启用，避免误杀整篇） |
| R6 | 同笔记同一小时零赞评论 ≥8 条（集中爆发） |
| R7 | 营销号昵称特征 |
| R9 | 不可改良项打标（物流 / 价格 / 客服 —— 保留但统计时剔除） |
| R10 | 完全重复的语料（同内容只计一条） |
| R11 | 纯话题标签串，剥掉 `#标签` 后没有实质表述 |
| R12 | 作者置顶 / 购买引导（去某宝、戳我、主页有…） |

## 九、两条统计纪律（决定数据可不可信）

1. **痛点桶走否定识别。** 「不紧绷」「不假滑」「没长脂肪粒」不会被算成痛点。

def clean_title(raw, hit_re, noise=()):
    """从搜索结果卡片的整块文本里剥出标题。

    卡片文本形如「标题\\n作者昵称\\n3 天前\\n1.2万」，

    keep = [p for p in parts if not TITLE_TIME_PAT.match(p)]
    if not keep:

        return None

    结构：昵称\\n正文（可能多行）\\n时间行\\n[点赞数][回复]
